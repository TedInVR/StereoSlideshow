Stereo Slideshow

User Guide · Version 0.27

Turn stereo photographs and side-by-side video clips into an animated slideshow, with titles, captions, music and optional red/cyan anaglyph output.

Permanent app and future updates

Extract the download and double-click Install or Update.command. The installer places one permanent Stereo Slideshow folder in Applications and opens its app. Put Stereo Slideshow.app from that folder into your Dock once. Use that app for everyday launches; the installer is only for setup and updates.

Keep the entire folder together: the app, Development, Runtime, Settings and Logs belong together. For an update, quit the app, extract the new download in Downloads and run its installer. It updates the same app path while retaining your preferences and captions. Do not replace your permanent folder by dragging a new folder over it in Finder. The update routine keeps a previous source backup in Updates.

Save and resume a project

File → Save Project (Command–S) saves the current work without rendering. The first save automatically creates a folder beside the first visual item, or beside the first music item if there are no visuals. With no imported items it uses Documents. The folder is named from the title, for example Family Vacation StereoSlideshow Project; without a title it uses Untitled. Existing folders receive a number so they are not overwritten.

Inside are a .stereoslideshow project file and a Media folder containing copies of all imported photos, video clips and music, including generated soundtracks. The original files stay untouched. The project stores media order, music order (including repeated tracks), captions and deliberate blank captions, individual clip-audio choices, title, colors, timing, stereo layout, animation, output settings and saved music style choices. Local ACE-Step setup and API credentials are not bundled.

Copies can use substantial disk space for large videos. A progress window shows which file is being copied, with byte progress for larger files; Cancel stops the save. On later saves, unchanged external sources reuse their existing copies. The project file is committed only after all required media is copied. A failed or cancelled save leaves the previous saved project file unchanged; incomplete first saves can leave a partial folder. Removed media copies are retained in the folder rather than automatically deleted.

Use File → Open Project… (Command–Option–O) and choose the .stereoslideshow file inside that folder. Move or copy the entire folder to keep it portable; do not move just the project file. Original source locations are recorded for save bookkeeping, but reopening uses the bundled relative paths. Missing bundled media is reported before the current work is changed. Opening restores the project; it does not start rendering.

File → Save Project As… (Command–Shift–S) lets you choose another name/location and creates a separate bundled project folder there. Once a project is saved, subsequent Save Project commands update it. An asterisk beside the project name indicates edits. If an already-saved project has unsaved edits, closing or opening another project offers Save, Discard or Cancel. Ordinary sessions that have never been saved as a project keep the previous close behavior; explicitly save them before closing if you want to resume them.

Finished video filenames

Exports begin with the opening title, followed by the format, output height and full finished duration. Example: Mom at the Beach_StereoSlideshow_Full_SBS_3D_1080p_4min.mp4. Four minutes and three seconds uses 4min03sec; a shorter video can use 44sec. Duration includes opening/title, full rendered timeline, closing fade and any final black tail, rounded to the nearest second. Resolution is the selected frame height, such as 540p, 1080p or 2160p.

Without a title, an eight-digit random number is used. Characters that are unsuitable for filenames are cleaned up, and very long titles are shortened for filesystem compatibility. Anaglyph files use Anaglyph_3D; the optional MKV uses YouTube_Full_SBS_3D. If a matching output already exists, a number is added to the title portion, preserving the earlier export. Changing the filename does not change stereo metadata or picture proportions.

Quick start

  1. Drop your full-SBS photographs into the main window, or click Add files…. You can also include SBS video clips and multiple music files.
  2. Drag rows to put the photographs and clips in your preferred order.
  3. Choose the seconds per photo, frame shape, background and animation. Five seconds is the initial photo default. Clips play in full in visual-ending mode and automatic-fit mode; a manual music-ending sequence can cut them short.
  4. Type an optional opening title. Click Captions… to add or edit text for individual items.
  5. Select the export formats. For your first test, use Full-SBS MP4 and 540 pixels high — quick test.
  6. Click Create slideshow. The output folder opens when the export finishes.

Your original photos, videos and music are not modified. Most settings are remembered when you create a slideshow. Captions are also saved when you save the caption editor.

Guided walkthrough

Choose Help → Guided Walkthrough… in the Mac menu bar. The walkthrough starts with your current media and settings and asks six sets of questions:

  1. Finished formats: SBS, anaglyph, and the optional YouTube compatibility copy.
  2. Media and order: add or drop photos and videos, rearrange rows, and choose which clips retain sound.
  3. Timing and appearance: photo duration, frame shape, resolution, animation, background, depth layers and closing fade. Set the video layout here too.
  4. Title and captions: choose the title, opening timing and colors; edit captions for the selected media.
  5. Music and saving: choose music or no music, then the output location.
  6. Review: check your choices and the item sequence. Click Create slideshow to apply them and render.

Next advances and Back lets you revise a choice. Invalid or missing required choices are explained before proceeding. Help opens this guide. Cancel leaves the main window's media, captions and settings unchanged. Changes made inside the walkthrough apply only when you finish it. Rendering begins only when you click Create slideshow.

Photographs, video clips and order

The main list shows filenames. Hover over a name to see its full location. Files from different folders may have the same name; their full locations are kept separately behind the scenes.

  • Photos: PNG, JPG/JPEG/JPS, TIFF, WebP and BMP. Input photos must contain two full-width eye images side by side. Half-SBS photos and anaglyph photos are not supported as stereo inputs.
  • Video clips: MP4, MKV, MOV, M4V, AVI, WebM, MTS and M2TS, with codecs your FFmpeg installation can decode. Use side-by-side stereo clips, not top/bottom, Blu-ray MVC/frame-packed, or VR180 projection video.
  • Music: MP3, M4A, WAV, AAC, FLAC, OGG and AIFF. Tracks are added to an ordered playlist. Drag music rows to change playback order.

New files initially sort alphabetically by their full path; drag rows to arrange the final sequence. Select rows and click Remove selected to remove them from the project, or Clear list to start another sequence. Neither action deletes source files.

Eye order and full/half SBS

Parallel left/right is the default. If the photos have the right eye on the left, check Input photos are cross-eye. Video eye order has its own checkbox. For horizontally squeezed video eye images, check Video clips are half-SBS. These video layout choices apply to every clip in the batch: use consistent layout and eye order within a batch. Photos remain full-SBS even when the video half-SBS option is enabled.

How clips play

A video is independent of the photo timer and plays in full in visual-ending mode. Automatic fitting also reserves its full duration. Manual music-ending mode can cut a clip short if the music ends first. Its eye images fit proportionally into the chosen frame and are centered against black, with bars where necessary. Clips have no duplicated photo background or photo animation. Cuts into and out of videos do not overlap their footage; adjacent photos use brief dissolves. Video is rendered at the slideshow's output resolution and 30 frames per second.

Expanded organizer and multiple music tracks

Click + Expand lists at the upper right of the content area. A maximized organizer shows your photos/videos and music playlist side by side. Drag rows or use Move up and Move down. Add and remove items in either list. Video checkboxes still control original clip sound. Save or − Return to main window applies the changes; Cancel discards them.

The main window also has a separate draggable music list, Add music, Remove selected music and Clear music controls. Add multiple audio files together, including WAV files. Tracks play sequentially in playlist order. Adding more music appends rather than replaces. The same track may be included more than once.

Each track shows its length, such as 4:03 (243 seconds), and the playlist header shows the total. Durations load in the background; a brief “reading durations” message is normal. Photo and video order is independent of music order.

Timing calculator and how the video ends

The calculator appears in a read-only box below Auto-Fit in Step 3. The box reserves room for eight lines; if wrapping or additional details exceed that space, scroll inside it to see the remaining text. You can select and copy the calculation. It shows photo count and time per photo, video clip time, opening time, closing fade, total playlist length and finished video length. It updates when the lists or relevant settings change.

Ending choiceBehavior
Visual sequence ends the videoPlays all photos at the manual duration and all clips in full, then adds the closing fade and one-second black tail. The ordered music playlist repeats as needed, or is trimmed and faded if longer.
Music playlist ends the videoUses one pass of the full playlist as the video length. The closing fade is inside the end of that duration. With manual photo timing, a short sequence holds its final frame; a long sequence can be cut short or have later items omitted. The calculator identifies either situation.

Check Auto-Fit photos to music (seconds per photo) to use music-ending mode and calculate photo timing for you. The Seconds per photo field displays the calculated duration and is disabled while Auto-Fit is checked. Turn Auto-Fit off to restore your last manual duration. The calculation reserves the opening, all full video clips and closing fade, then divides the remaining time among photos. For example, a 243-second playlist with a 7-second opening and 6-second closing leaves 230 seconds for photos when there are no clips. With 34 photos, that is approximately 6.765 seconds per photo.

Photos may differ by one video frame so that the total matches. Video lengths and captions are not sped up or slowed down. If the music cannot accommodate all full clips, opening, fade and at least one frame per photo, automatic fitting stops before rendering and asks for more music or shorter fixed sections. Music ending requires music; automatic photo fitting requires at least one photo.

Duration previews use source metadata. At export, a music-ending soundtrack is decoded and its length rechecked, which removes compressed-audio padding discrepancies. The finished timeline matches within one output video frame. New playlist and timing choices are also available in the Guided Walkthrough; its review shows the calculation.

Create music to fit your slideshow

After adding photos and videos and setting the photo duration, click Create music to fit this slideshow… in Step 2 (Music playlist). The same button is available in the walkthrough's Music step.

  1. Review the displayed soundtrack length. It includes all photos at the displayed seconds per photo, full video clips, the blank opening, title when present, closing fade and one-second black tail.
  2. Choose an Era, Genre and Mood. You can type your own choices. Add an optional description, such as preferred instruments or a musical atmosphere. Choose Instrumental, Write a song about a topic, or Use my lyrics. Song modes offer vocal preference and language controls.
  3. For first-time setup, choose the installed ACE-Step 1.5 project folder containing acestep/api_server.py. The app tries to detect common install locations. Portable installations with either python_embeded or python_embedded are supported; broken copied .venv links are skipped. Keep the default local address unless your API server uses a different port. Most local installations do not need an API key.
  4. Click Generate music. Model loading can take several minutes. The app stays responsive, shows progress messages, and lets you cancel. It starts the local REST API using ACE-Step's installed Python environment. It stops the engine it started when generation completes, fails or is cancelled. An API server that was already running is left running.
  5. Click Play preview and Stop preview to audition it. Generate another take creates a new file. Click Use this music to replace the current playlist with the selected take, or Cancel to keep the existing playlist.

Music follows the visuals: accepting a take selects visual-ending mode and turns Auto-Fit off, preserving the photo duration used for the request. This prevents photos and music from each trying to determine the other's duration. If you later change photo counts, photo time, clips, title or fades, reload a take and choose Extend or Trim, or generate a new take to match the changed timeline. Ordinary soundtrack looping/trimming still works if you keep an older take.

Each request uses a fresh random seed, but quality and how closely the model follows an era or genre vary. The audio is prepared as an exact-length, 48 kHz stereo 24-bit WAV. Requests shorter than ten seconds generate ten seconds and trim to the timeline. Instrumental timelines over ten minutes use balanced sections with two-second crossfades. Vocal songs currently support up to ten minutes. These are separate matching sections, not a guaranteed seamless single composition. If ACE-Step returns an unexpectedly short instrumental section, it repeats to fill its allotted time. Vocal takes more than a quarter-second shorter than the requested timeline are rejected rather than looping verses. Small rounding gaps can be padded at the end. Slideshow export applies the usual fade-in, final fade and clip-audio ducking.

Takes are kept in Generated Music inside the permanent Stereo Slideshow folder. A small JSON file beside each WAV records the prompt and requested duration. Cancelling the dialog or generating another take does not delete earlier WAV files. Generated files and local generator settings are excluded from Git and release packaging.

Music generation connects to the official ACE-Step 1.5 REST API. Its Gradio browser interface (often port 7860) is different from the API (normally port 8001). An older ACE-Step installation without the API may need updating or dependency setup. This feature reuses a separately installed local engine; it does not bundle models, sign up for Suno, or call a paid music service. Model downloads may still be needed by ACE-Step if its models are not installed. See ACE-Step API documentation.

Instrumentals, topic-based songs and supplied lyrics

  • Instrumental: requests music without singing or speech. Vocal fields are hidden. If you use a saved description containing vocal directions, select a song mode for singing or remove those directions for instrumental use.
  • Write a song about a topic: enter a subject such as childhood summers at Whalom Park. ACE-Step writes lyrics and generates the audio together. This needs its language-model component. When the app starts an engine for topic mode, it requests language-model loading; this can take longer and may require model downloads. An already-running API must have its language model available. The app does not use the random-example endpoint to substitute unrelated lyrics.
  • Use my lyrics: paste your lyrics. Optional tags such as [Verse 1] and [Chorus] help indicate structure. The supplied text is sent unchanged, without asking ACE-Step to rewrite it. The amount of text should fit the target duration; a short song can rush, omit or mispronounce words. Exact audio duration is enforced, so the final trim or slideshow fade may cut off late words.

Vocal preference offers No preference, Male lead, Female lead, Male and female duet, and Group / choir. These are prompt directions, not guarantees of a particular singer or perfect separation of voices. The language dropdown includes English, Spanish, French, German, Italian, Portuguese, Japanese, Korean, Mandarin Chinese and Hindi; results vary.

After a topic-generated take, returned lyrics appear in Lyrics to review. Click Edit and use these lyrics for another take to switch to Use my lyrics, edit the words and regenerate. Generating again in topic mode requests fresh lyrics. Preview and Use this music still refer to the last successfully generated audio, not to ungenerated edits. Lyrics and selected voice/mode/language/topic are saved with project music choices and the take's JSON record. If the API does not return lyrics text, the take may still be auditioned; no guessed transcript is substituted.

Saved musical descriptions

The Saved descriptions dropdown contains seven starter descriptions supplied for this app: two nu-disco/K-pop arrangements, two ska/electroswing arrangements, J-pop, hypnotic synthwave and Dixieland. Their full wording is retained in the description editor.

  1. Choose a saved description to load its text. Era, genre, mood and voice preferences stay as selected. For a detailed preset, choose Genre → Use description only to avoid adding a conflicting broad genre; Any era is available if the description should establish its own era.
  2. Edit freely in Your description. Loading text does not change the saved item. Command–Z can undo a loaded description.
  3. Click Save description…, enter a name, and save. To update an existing name, save with that name and confirm replacing its text. Use another name to keep both versions.
  4. Remove deletes the selected saved item after confirmation, while keeping the editor's text.

The list is personal and shared across projects on this installation. It is retained in Settings/music_descriptions.json through app updates. Deleted starter entries stay deleted after the list is saved. A project stores its currently used description, not the entire personal description collection. Saving a description does not generate music or alter existing audio. Generate, progress and preview controls remain below the scrolling settings pane.

Save, reload and edit an audio take

The Audio takes — keep, reload and edit section is at the top of the music window. Every generated take is kept automatically, even after you try another or cancel the window. Select an earlier file in Saved takes and click Load take. Use Import / reload audio… for a file from elsewhere, including your own recordings in MP3, FLAC, WAV, M4A, AAC, AIFF, OGG or other supported formats. An imported recording is copied into Generated Music; the external original stays unchanged.

Save Audio As… exports the previewed result to your chosen folder as WAV, FLAC or MP3. Choose a descriptive name. A WAV-to-WAV save copies the bytes; MP3 is a lossy export. A companion JSON file retains available lyrics, musical description and settings. Keep both files together when moving or sharing an editable take. Import the audio file to reload those settings; do not select the JSON. Old takes with only a prompt can recover that prompt as the description. Lyrics are recovered only if they were saved, not transcribed from arbitrary imported recordings.

Source identifies the recording being edited. A successful edit becomes the previewed result, while the source stays fixed so you can compare multiple attempts. Click Use previewed result as editing source when ready to build on that result. Use this music adds the previewed audio to the slideshow. Unsaved changes to the text or operation controls do not alter that audio.

Adding instruments requires ACE-Step's acestep-v15-base model. The app starts Base for that operation and may download its model files on first use. Base can take more time and memory than Turbo. If an API server is already running with Turbo, close that separate API and retry, or load Base there first. The app checks that Base is available before requesting a stem. Other AI edits use the current/default engine's Repaint task. Older ACE-Step installations may need updating for these tasks; a failure leaves your source intact.

AI edits currently support source and result lengths up to ten minutes. Trim can make longer recordings shorter. Topic-based lyric writing is for new songs; for an edit, select Instrumental or supply lyrics yourself. All edits create new WAV takes normalized to stereo 48 kHz, 24-bit PCM. Retaining decoded audio does not mean retaining the original compressed MP3 bytes. Musical continuity, timing of revised words, and accompaniment quality depend on ACE-Step; audition each take. These are audio-file edits, not a multitrack DAW session. Keeping the companion JSON allows settings and lyrics to reload; it does not recreate the model's internal session.

One-time Google setup

This release uses your own Google Desktop OAuth client. No shared Google project or credentials are bundled. Rendering, music generation and existing exports do not need this setup. Google can change console labels; the important choices are a Desktop app client, YouTube Data API v3, and your own Google account as an allowed test user.

  1. Open Google Cloud Console, sign in and create or select a project named, for example, Stereo Slideshow.
  2. Under APIs & Services → Library, find YouTube Data API v3 and click Enable.
  3. Open Google Auth platform (or OAuth consent screen). Complete its setup with an app name and your contact email. For a personal Google account choose External audience. While the app is in Testing, add the Google email you use for your YouTube channel under Audience → Test users.
  4. Under Data Access, configure the scopes https://www.googleapis.com/auth/youtube.upload and https://www.googleapis.com/auth/youtube.readonly. The first permits uploads; the second lets the app identify the destination channel. Neither is a request for your Google password.
  5. Under Clients → Create client (or Credentials → Create credentials → OAuth client ID), choose Desktop app. Name it Stereo Slideshow and download its JSON. Do not choose Web application or create only an API key.
  6. In Stereo Slideshow's YouTube window, click Choose Google client JSON… and select that downloaded file. Click Connect / change channel…. Your default browser opens Google's sign-in and consent pages.
  7. Select the intended account/channel, including the appropriate Brand Account if Google offers that choice. Approve both requested YouTube permissions. Return to the app and check its displayed channel name and ID. No video has been sent during connection.

A personal test client may show an unverified-app warning. Check that the app/project is the one you created. Google can require verification for broader distribution or sensitive-scope use; do not assume a personal test client is ready for public release. Testing-mode authorizations can expire after seven days, requiring reconnection. If Google refuses sign-in, check the test-user list, enabled API and Desktop client type. Google's upload quotas, account limits and access rules still apply. See desktop authorization documentation.

Review and upload

  1. Check the displayed destination channel. Use Connect / change channel… to select another; Disconnect removes the local connection and attempts to revoke Google's grant.
  2. Select your finished rectangular SBS video. Confirm left-eye-first order. Select Full-SBS for this app's normal MP4s or Half-SBS for externally squeezed input. Do not choose an anaglyph, cross-eye or VR180 file.
  3. Review the YouTube title, which defaults to the slideshow title or filename prefix. It must fit YouTube's 100-character limit.
  4. Edit the reusable description template, then click Apply template. The tokens {title} and {filename} insert the current values. The Video description below is the exact description submitted; edit it freely. Save template and default tags keeps those defaults for future uploads. It does not change existing YouTube videos.
  5. Choose Private, Unlisted or Public. Each new upload starts at Private. Explicitly select whether the video is made for kids. Use the altered/synthetic-content disclosure when required; YouTube lists synthetically generated music as an example. For tracks currently in Generated Music, the app preselects that disclosure, and you can review it.
  6. Click Upload to YouTube. A tagged MKV working copy is prepared without re-encoding the image or audio. The upload runs in the background with progress and automatic retries for interrupted chunks. Keep the app open. Cancel stops subsequent work; an in-flight request can take up to 30 seconds to return. If the final chunk was already received, a video may exist despite cancelling—check Studio before retrying.
  7. When YouTube acknowledges the upload, click Open uploaded video. YouTube still needs to finish processing; 3D may become available later. Acknowledgement is not a guarantee of completed processing or recognition. Edit the title, description, visibility and other details later in YouTube Studio.

The working copy reuses this app's explicit MKV stereo_mode=1 approach and verifies left/right stereo metadata before upload. It preserves the per-eye display ratio; the original Full-SBS file is unchanged. The upload copy can look squeezed in ordinary desktop players. The ordinary Full-SBS MP4 is intended for normal-proportion local playback; do not assume every such MP4 already carries the same YouTube tagging.

What does the audience question mean?

The uploader asks whether you made the video specifically for children. For a general-audience slideshow not directed at children, choose No — general audience, even if children could watch it. This is different from an age rating. Click What does this mean? beside the choice for examples, mixed-audience guidance, effects on comments and advertising, and official YouTube links. The help window does not change your selection; you must still choose the audience for each upload.

Upload when rendering finishes

Check Upload to YouTube after this render in the main Export section, then click Create slideshow. First review the same channel, title, exact description, audience, disclosure and visibility controls. Click Use these settings for this render to authorize that one upload. Cancelling this review returns without starting the render. The app ensures a Full-SBS output is created, renders locally, and uploads only after rendering succeeds. For this pre-render review, {filename} uses the proposed title because the final filename does not exist yet.

This permission applies to one render only. The checkbox resets once the render starts, and the queued upload is discarded if rendering fails or is cancelled. It is not saved into projects or silently re-enabled on the next launch. A channel-ID check immediately before upload prevents sending a previously reviewed plan to a different connected channel. Local finished files remain available if uploading fails. Connection retries resume chunks within the current session; restart/quit recovery of an unfinished upload is not included in this release.

YouTube data and privacy

Uploads go directly from your Mac to Google's YouTube API. This app does not operate an intermediary upload server or send your videos to the developer. Access and refresh tokens are stored using macOS Keychain; there is no plaintext-token fallback. A local Desktop client configuration, your description template/default tags, and a small history of uploaded video links/titles are stored in the app's Settings folder. They are excluded from source releases and projects. Temporary tagged upload copies are removed when an upload attempt ends. Original media, generated takes and finished local exports are retained.

Disconnect removes the locally stored authorization and attempts remote revocation; if offline, also review Google Account connections. Disconnect does not delete uploaded videos. Those are managed in YouTube Studio. Local history is limited to the latest 100 entries and is not synced by the app. Use of the YouTube integration is subject to the YouTube Terms of Service and Google Privacy Policy.

This release's OAuth flow, metadata preparation, upload protocol, cancellation and UI were tested with simulated Google responses and real FFmpeg remuxing. A live Google connection, Keychain prompts and a private test upload must still be checked on the Mac. VR180 cinema rendering and mixed VR180 footage are planned for the next phase; they are not added by this uploader.

Music and individual clip sound

Each video row has a sound checkbox. Checked retains that clip's original audio. Unchecked mutes the clip's audio while allowing background music to continue. Photos have no sound checkbox.

  • Mute all clips unchecks all video sound boxes.
  • Enable all clips checks them and enables the master clip-sound control.
  • Allow checked clips to play sound is a master switch. Turn it off to mute all clips without changing their individual selections.

Music fades in and fades with the picture at the end. In visual-ending mode, the entire playlist repeats if needed. In music-ending mode it plays once and determines the finished video length. During a clip with retained audio, background music drops to 25%; after the clip it returns to normal. A muted clip or one without audio does not lower the music. Clip sound choices are remembered for those source paths after rendering.

Use Clear music for no soundtrack. Without music, retained video sound still plays and photo sections are silent. For a completely silent slideshow, remove the music and mute all clips.

Frame shape, resolution and motion

ControlWhat it does
Frame shape per eye4:3, 1:1, 16:9 or 2:1. These describe each eye, not the width of the packed pair. The full-SBS frame is twice as wide. 4:3 is a useful starting point for mixed collections.
Output resolutionChoose 540, 1080 or 2160 pixels high per eye. Width follows the frame shape. Quick test is faster and smaller; higher resolutions take longer and need more space.
Seconds per photoManual display time for each photograph. It is unused when automatic fitting is enabled. In visual-ending mode, the closing fade adds time after the final item.
Zoom and panAlternates stronger zooms with side or vertical drift. Zoom-in ends with about 10% of the original height cropped at the top and bottom. Wide photos may also crop at the sides. Some photos reverse the zoom.
Side-drifting photosCan reach 96% of frame height, limited to 80% of frame width. They start near a 10% side margin and drift inward. Larger images may extend past the midpoint.
Subtle zoom and panA small 2% zoom change and subtle travel. Pan distance (subtle mode) applies only to this style: No pan (zoom only), Very small or Small. The maximum travel is 0%, 0.3% or 0.6% of the frame dimension, reduced where margins are limited.

Both eyes use matching motion and timing. Images keep their proportions. Zoom changes the visible crop and size; it does not create new perspectives within the original scene.

Photo backgrounds

  • Sharp moving current photo: a full-brightness enlarged copy fills the background, alternating slow zoom and horizontal/vertical drift. Foreground remains separate.
  • Blurred current photo: an enlarged, darkened and softly blurred copy fills unused space.
  • Previous photo grows: the preceding photo slowly enlarges behind the new one. The first photo, or a photo following video, uses its own background.
  • Solid color: use the background color selected in the app.

Photographic backgrounds are cropped to cover the frame. Video backgrounds always remain black.

Stereo layer separation

With 3D layers enabled, the background plane moves behind the stereo window. The main photo retains its original stereo alignment. Choose Subtle, Medium or Strong separation. Captions with the front-of-screen option enabled sit in front of the window. Source photos already contain depth; a strongly protruding subject can still come forward of caption text. Check the result in your stereo viewer and adjust the separation if needed.

Opening title and captions

Title

Enter an optional opening title. A blank title skips the title portion. Choose the blank opening time, title duration, background color and title color. The title fades in and out in both eyes. Its depth movement can approach throughout, or approach and then retreat.

Captions for specific items

  1. Add media, then click Captions….
  2. Select a filename on the left. Newly captioned items start with the filename without its extension or path: Mom at the Beach.jpg becomes Mom at the Beach.
  3. Edit the text. Use line breaks if useful. Leave blank or click Clear this caption for no caption.
  4. Select another item to edit it. Click Save when finished, or Cancel to discard the editor's changes.

Existing text and deliberately saved blanks remain unchanged on reopening. Captions allow up to 400 characters, wrap automatically and shrink if necessary. Short captions are easier to read. No filename captions are added to exports until you open and save the caption editor.

Captions appear near the bottom, in both eyes, as white text on a translucent dark backing. They stay stationary as the photograph moves. Check Place captions slightly in front of the screen for front-window depth, or uncheck for screen-plane placement. One caption stays for an entire video; timed dialogue subtitles within a clip are not provided. Captions are part of the exported picture in all formats, and the final caption fades with the closing image.

Closing fade

Closing fade to black + silence defaults to six seconds and can be set from 0–30 seconds. In visual-ending mode, after the final photo's normal duration its final composition holds as picture and music fade together, followed by a one-second black/silent tail. In music-ending mode the fade occupies the final seconds of the playlist and there is no added tail. Set zero to skip the added fade.

In visual-ending mode, if the last item is a video, it plays in full first. Its final frame holds for the closing fade. Original clip sound ends with the clip; background music continues through the fade.

Troubleshooting

Odd-width stereo photos

Photos with an odd total pixel width are accepted. The app omits the single column at the center join during rendering so both eye images have equal dimensions. Your source file is unchanged. All photos are decoded and checked before the slideshow encoder starts, so a damaged photo is reported early.

A render fails

The error dialog shows a short explanation and a visible Close button. Press Escape to dismiss it. Technical output is kept in a diagnostic report under the permanent app folder’s Logs directory. Use Show technical details for a scrollable view, or Open Logs folder to find and share the report. Raw rendering progress is not displayed in the popup.

What does “Video built: 12 / 89 seconds” mean?

It means 12 seconds of the finished 89-second timeline have been built. It is not elapsed time or a countdown. Later stages add audio and create exports, so the progress percentage is an approximate phase indicator.

The SBS picture looks narrow or vertically stretched

Open the newly created _FullSBS.mp4 for ordinary local viewing. The compatibility MKV deliberately uses a different display convention and may appear squeezed. Check the player's aspect override too. Videos that look wrong may need the half-SBS input option changed before rendering.

Depth seems reversed

Check input eye order. Photo and video cross-eye controls are separate. Full-SBS and half-SBS are separate from eye order. The output is always left-eye first.

A clip is silent or the music does not lower

Check the clip's row checkbox, the master clip-sound switch, and whether the source clip contains an audio track. Muted clips intentionally leave music at normal level.

Rendering is slow or appears stuck

Try a few items at quick-test resolution. Large photos, long clips, 2160-high output and additional exports can take longer. Use Cancel if progress stops unexpectedly. Completed exports remain available; temporary work is discarded on normal cancellation. If the app becomes unresponsive, force quit it. Your original media is unchanged.

Installation or launch fails

The installer requires a working Python 3.9–3.14 and Homebrew FFmpeg/FFprobe. It installs Pillow and PySide6 in an isolated environment. Installation needs internet; rendering runs locally. Copy any installer error into your support conversation.

The permanent folder is /Applications/Stereo Slideshow, or ~/Applications/Stereo Slideshow when the system Applications location is not writable. It contains the app, Development, Runtime, Settings, Logs and Updates folders. Use Help → Open Stereo Slideshow Folder to find it. Your diagnostic log is Logs/app.log; preferences and captions are in Settings/settings.json. Quit before installing an update.

This guide describes version 0.27. Original stereo depth and playback-device behavior can affect the viewing result.
